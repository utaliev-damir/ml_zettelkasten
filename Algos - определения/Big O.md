## Определение
Существует такая константа $C > 0$, что начиная с некоторого объёма входных данных $n_0$ функция $C \cdot g(n)$ становится больше или равна $f(n)$.

$$
f(n) \in O(g(n)) \iff \exists \; C > 0,\ n_0 : \; \forall n > n_0 \quad 0 \leq f(n) \leq C \cdot g(n)
$$

## Интуиция

Асимптотика О большое нужна для оценки верхней границы сложности алгоритма. Вместо того чтобы читать тысячи строк кода и подсчитывать, сколько выполняется операций, мы находим в коде функциональную зависимость от количества входных данных и через неё оцениваем сложность.

$O$ говорит только о поведении при больших $n$. На маленьких входах алгоритм с «худшей» асимптотикой может работать быстрее.

## Основные свойства
* Можем считать сложность по самой быстрорастущей функции: $f_1(n) \ge f_i(n) \to O(f_1(n) + f_2(n) + \dots + f_m(n)) = O(f_1(n))$
* Константы не влияют на асимптотику: $O(C \cdot f(n)) = O(f(n))$
* Произведение: $O(f(n)) \cdot O(g(n)) = O(f(n) \cdot g(n))$
* Транзитивность: $f \in O(g),\ g \in O(h) \to f \in O(h)$

## Правила и преобразования
Типичные правила работы с этим понятием.

* Отбрасываем младшие слагаемые и коэффициенты: $3n^2 + 5n + 2 \in O(n^2)$ (например, $C = 10,\ n_0 = 1$)
* Основание логарифма не важно: $\log_a n = \frac{\log_b n}{\log_b a}$, т.е. отличается на константу, поэтому пишут просто $O(\log n)$
* Последовательные участки кода складываются: $O(f) + O(g) = O(\max(f, g))$
* Вложенные циклы перемножаются: цикл по $n$ внутри цикла по $n$ даёт $O(n^2)$
* Иерархия роста: $1 < \log n < n < n \log n < n^2 < 2^n < n!$
