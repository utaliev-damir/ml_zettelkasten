# C-order и F-order

в памяти массив — просто ряд ячеек, никаких строк и столбцов там нет. Порядок (C или F) — это правило, как перевести индексы `[i, j]` в номер ячейки.

## Две формулы

Для формы `(R, C)`:

```
C-order:  ячейка = i*C + j     быстрее всех крутится последний индекс
F-order:  ячейка = i + j*R     быстрее всех крутится первый индекс
```

Одни и те же данные `A B C D E F` (ячейки 0–5), форма `(2, 3)`:

```
C-order        F-order
A B C          A C E
D E F          B D F
```

## Раскладка ≠ обход

- **Раскладка** — свойство массива: какая из двух формул у него записана. Байты при этом никуда не переставляются, их порядок в памяти всегда один и тот же — меняется только правило, как из индексов получить номер ячейки. Массив с C-формулой называют `C-contiguous`, с F-формулой — `F-contiguous`.
- **Обход** — свойство операции: в каком порядке перебираются индексы.

Подряд по памяти получается только там, где обход совпал с раскладкой:

```
уложен C, обход C  →  0 1 2 3 4 5   подряд
уложен F, обход F  →  0 1 2 3 4 5   подряд
уложен C, обход F  →  0 3 1 4 2 5   прыжки
уложен F, обход C  →  0 2 4 1 3 5   прыжки
```

## Зачем это знать

- **Скорость.** Подряд процессор читает быстро, прыжками — заметно медленнее.
- **Скрытые копии.** Многим операциям нужен непрерывный кусок памяти. Если его нет, NumPy молча создаёт копию.

Проверить раскладку: `a.flags` (`C_CONTIGUOUS`, `F_CONTIGUOUS`).

## Транспонирование

`.T` не двигает данные — оно меняет формулу: `a.T[i, j] = a[j, i]`, коэффициенты в формуле меняются местами. Поэтому C-contiguous массив после `.T` становится F-contiguous, и наоборот. Байты те же, изменилось только правило чтения.
